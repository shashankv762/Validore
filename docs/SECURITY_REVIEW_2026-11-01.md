# Security review: privacy, research and founder interviews

Scope: the local Next.js 16.4.3 application and this privacy/data/interview extension, reviewed November 1, 2026. Source changes and regression tests reduce concrete data-disclosure, request-abuse and duplicate-work risks. Production database permissions, provider settings and hosted behavior remain unverified for this revision. This is a development security review, not a penetration-test certificate or guarantee.

## Verification and limits

The current local suite has **487 passing tests and eight explicitly skipped database cases**. Tests cover anonymous access, owner predicates, invalid/stale versions, mutation limits, deleted-interview races, private-context separation, provider/search limits, cached data reuse, credit reservation/refund consistency and safe exports. A real-SDK synthetic pipeline proves the internal connections; it does not establish external provider behavior or a hosted queue's delivery guarantees.

Public production pages and synthetic private UI components passed 60 browser checks. The built standalone smoke checks public content, dynamic CSP, signup fields, no-store responses and request boundaries. Production dependency audit reported **zero vulnerabilities across 422 production dependencies**. A limited filename/signature scan found no selected live-key patterns or private-key blocks in nonignored source. None of these is a full historical secret scan or exploit assessment of hosted infrastructure.

The refreshed **full** dependency audit still reports **20 moderate findings**, all in development tooling, with no high/critical findings. Two underlying advisories propagate through those packages: [minimatch glob amplification](https://github.com/advisories/GHSA-g3hv-75wg-m249) in ESLint/TypeScript lint dependencies, and [legacy esbuild development-server access](https://github.com/advisories/GHSA-67mh-4wv8-2f99) beneath `@esbuild-kit/core-utils`/Drizzle Kit. The reported minimatch fix requires version 11 while some consumers require the older function API. npm's proposed automatic fixes include incompatible ESLint, Next lint-config and Drizzle Kit downgrades. No forced override or toolchain downgrade was applied. Track compatible upstream upgrades, keep tooling/dev servers private, and process only trusted configuration until a separately tested migration resolves them. This does not change the production-only audit result.

The final browser-asset check inspected 41 built files and found no exact configured private credential values or selected server-research markers. Documentation validation found all 67 local file links resolve. These narrow packaging checks do not prove the absence of every secret encoding or replace inspection of the actual hosted deployment.

No production SQL, role tests, storage inspection, live payment requests, customer data changes, SMTP tests, external deployment or new application AI calls were performed. Existing account/market-memory live-model evidence belongs to the preceding release and is linked separately in [release evidence](PRIVACY_DATA_RELEASE_2026-11-01.md).

## Required hosted and operational checks

1. **Database:** back up the reviewed target, apply migration 0003, run `db:verify`, and test anonymous/authenticated Data API denial on every application table. Check real grants, views, RPC functions, exposed schemas and storage buckets. Source RLS declarations cannot prove the live state. Test account A against account B's idea/interview/report/export references.
2. **Signup and consent:** verify confirmation, rate limits, CAPTCHA/abuse configuration and supported auth flows in Supabase. The public Supabase auth endpoint can bypass the app's signup-form network quota. Email acceptance is stored in mutable Supabase user metadata, not an immutable legal ledger. Google sign-in may provision accounts; decide and enforce any formal acceptance requirements across that path and direct auth access.
3. **Provider and queue privacy:** configure retention/training/transfer terms for the selected gateways, downstream models and Inngest. Private founder context can appear in durable steps and earlier reports. Clearing an interview does not retroactively purge those copies or downloaded files. Avoid logging prompts and raw provider responses.
4. **Privacy operations:** assign an owner to the privacy mailbox; verify requests before exports/erasure; define correction, account closure, backup expiry and legal-retention exceptions. Full-account self-service erasure is not implemented. Indian legal requirements and any required operator/address/tax details need operating-business review.
5. **Browser policy:** dynamic auth/dashboard pages use nonces. Public prerendered pages still permit inline scripts for Next.js hydration, and inline styles are allowed. This is a remaining hardening boundary, not a universal strict CSP. Supabase browser session cookies are not HttpOnly because the browser client uses them; XSS prevention remains important.
6. **Hosted behavior:** test final-domain email/Google/recovery, origin forwarding, Inngest registration and actual delivery, retries/stale jobs, concurrent credit accounting and private exports. Keep one active production worker/cron schedule during cutover. Stripe purchases require staging and live fulfillment/idempotency checks before accepting payments.
7. **Capacity and response:** confirm live quotas and fallback availability, enable failure/cron/webhook monitoring, and rehearse restore/key rotation. Recorded validation tokens omit some unreported/failed or non-validation usage. A historically free model or a passing dependency audit does not guarantee future pricing, availability or security.

Follow the current [Cloudflare launch guide](GO_LIVE.md) for deployment, nameservers, secrets and hosted acceptance. Earlier checks above do not verify the current Worker build.
